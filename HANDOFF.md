## What this is
An offline-first Arabic (RTL) web app / PWA that guides a 10-step self-healing journey, tracks check-ins, and builds a printable summary for the user's therapist. All data stays on the device (IndexedDB). It is a supportive tool, not therapy.

## Hard rules (from the spec)
- `<html lang="ar" dir="rtl">`; all user-facing copy in simple standard Arabic, first person; digits shown Arabic-Indic, stored as normal numbers.
- Intensity is an integer 0..10. Day keys are `YYYY-MM-DD` in local time.
- Privacy defaults: `share=false`, `forNextSession=false`; session notes never enter the summary.
- No streak counter; empty days are hidden, never described as failure.
- No analytics, no network calls with user data, fonts self-hosted.
- Touch targets >= 44px, contrast >= 4.5:1, real buttons/labels.
- Never write help-line phone numbers from memory.

### Android splash fix (2026-11-01, owner reported it "still not working" on the phone)
Cause (recorded on the owner's Android 16 phone with `adb shell screenrecord`): the system splash only shows the «ر» mark, and the animated web splash (name, tagline, note) was removed at the same instant the system splash hid, so it was never seen. Fix: `handOverSplash()` in `src/platform/launch.ts` hides the system splash as soon as the web splash has painted (`releaseNativeSplash` minimum now 0), then `hideSplash(..., {native: true})` keeps the animated web splash for `ANDROID_WEB_SPLASH_MS` (1500 ms, counted from the hand-over) before fading it. Browser behaviour is unchanged (`SPLASH_MIN_MS`). Tests first (5 red, then green): `splash.test.ts`, `launch.test.ts`. Evidence: 787 unit tests, TypeScript clean, new recording shows mark, then animated splash, then Home. The first ~1 s of the system mark is Android's own cold start and cannot be shortened by the app.
